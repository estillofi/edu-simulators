# Спека для разработки: живой экран учителя, kori-trace и педагогические измерения

Версия 1 · 13.11.2026 · прототип: этот репозиторий (`server/`, `shared/`, `teacher/`). Задача разработки — перенести в LMS Кори и практику Кори, где ученики общаются с Кори.

## 1. Что передаём

| Часть | Файл-образец | Что взять |
|---|---|---|
| Формат событий v1 | `docs/kori-trace.md`, `shared/kori-trace.js` | поля и типы событий; клиент можно переписать |
| Хранилище | `server/schema.sql` | сырые события без потерь + производные представления |
| Сигналы и метрики | `server/signals.mjs` | чистые функции без зависимостей, пороги в `RULES` |
| Живой экран | `teacher/index.html` | макет и поведение: три сигнала, карточки, карта ошибок, «Измерения» |
| Кори-компаньон | `shared/kori-companion.js`, `shared/kori/*.webp` | правила появления и поз |
| Проверка без детей | `server/simulate.mjs` | 25 ботов с профилями ошибок |

## 2. Поток данных

```
ученик (практика / тренажёр / диалог с Кори)
  → событие kori-trace (POST, пачками, повтор по event_id отбрасывается)
  → events (сырые)  → живой экран учителя (push ≤ 5 с: SSE/WebSocket)
                    → ночной пересчёт: посильность, успеваемость, дельта, прогресс → подбор заданий Кори, отчёт методисту
```

**Для диалога с Кори** — те же события: реплика ученика с проверяемым ответом = `attempt` (ответ, верно/нет, ID заблуждения из узла); ступень помощи Кори = `hint` (номер ступени); задача закрыта = `item_end`. Тогда диалог и тренажёры живут на одной шкале.

## 3. Событие (обязательные поля)

`event_id, ts, type, session_id, student_ref, class_ref, trainer|source, item_id, skill, node, level, template` + по типу: `attempt_no, correct, answer(≤80), misconception, latency_ms` / `hint_level` / `solved, attempts, hints, superscore, duration_ms`. Пульс `heartbeat{idle_ms}` раз в 15 с.

Правило: недописанный ответ (скобки не раскрыты, ввод не прочитан) — не попытка.

## 4. Педагогические измерения (по Д. Аббакумову, «Психометрика в EdTech», гл. 7–9)

Все метрики — 0..1, одна шкала интерпретации:

| Значение | Категория |
|---|---|
| < 0,45 | fru — фрустрирующая |
| 0,45–0,70 | sub — субоптимальная |
| 0,70–0,90 | opt — оптимальная |
| ≥ 0,90 | bor — скучная |

**Значению доверяем** (`valid = yes`), если стандартная ошибка `se = sd / sqrt(n) ≤ 0,075` и `n ≥ 15`. Иначе — `not yet`, на экране «мало данных», не цифра.

| Метрика | Формула | Где применяем |
|---|---|---|
| Супербалл `score_ij` | 1 — решено с первой попытки без подсказок; 0 — не решено; между — штрафы за попытки и подсказки (у нас −0,25 за каждую, параметр аналитика) | каждое закрытое задание |
| Посильность `cf_i` | среднее `score_ij` по ученикам на задании; агрегаты — по уроку, теме, типу задания, шаблону | контент; ревью методиста |
| Успеваемость `lp_j` | среднее `score_ij` ученика; **текущая** (все задания) и **накопительная** (`cummean` по времени, тренд вниз = риск «отвала») | ученик, группа, класс |
| Дельта `delta_ij` | `score_ij − cf_i`; < −0,1 negative · > −0,1…0,1 neutral · > 0,1 positive; по уроку — среднее | персонализация, кому давать доп. практику |
| Прогресс | `prog = заданий_взаимодействовал / заданий_в_теме` | доля пройденного |
| Скорректированный прогресс | `cor_prog = prog × lp_j` | показывать ученику рядом с `prog`: разрыв = где повторить |

Практические правила книги, которые закладываем в экран: посильность — помощник, а не начальник (подсказывает, где смотреть); задачи, которые никто не решает без подсказки, — сигнал вынести подсказку в основную часть; успеваемость — для адресной помощи тем, у кого fru/sub, и для привлечения opt-учеников помощниками.

## 5. Живой экран: три сигнала (поверх метрик)

Пороги — гипотезы прототипа, вынести в настройки:
- **Застрял** — 3 неверные попытки подряд в одном навыке; или один ID заблуждения 2 раза в последних 5 попытках; или > 2 мин над заданием и > 1,5 мин без попыток.
- **Угадывает** — ≥ 2 неверных ответа быстрее 5 с из последних 4; или подсказка < 6 с после показа — дважды.
- **Освоил навык** — BKT P(L) ≥ 0,95 или 3 задания подряд со `score = 1` на уровне Б/В; минимум 4 задания; нет сигнала «угадывает».

Экран: сверху счётчики сигналов (кнопки-фильтры) → карточки учеников по срочности (застрял → угадывает → работает → не на странице) с последними 10 результатами → карта ошибок класса (сколько учеников, по ID) → вкладка «Измерения» (успеваемость + категория + valid, дельта, посильность шаблонов). Карточка ученика: последние 8 попыток с ответом, временем и заблуждением.

## 6. Кори на странице ученика

Машет при входе; говорит только подсказками (3 ступени: вопрос → правило → шаг этого задания); на верный ответ — поза без слов (серия ×5 — кубок, новый уровень — «ура»); на ошибку не реагирует; кнопка «Тише». Без очков и рейтингов.

## 7. Приватность (жёстко)

`student_ref` — псевдоним; имена только у учителя (в прототипе — `localStorage`). Наружу класса — агрегаты от 3 учеников. Сервер — в РФ (152-ФЗ ст. 18 ч. 5), согласие родителей. Без камер и распознавания эмоций.

- 25 ботов `simulate.mjs` → на экране появляются все три сигнала, карта ошибок, valid = not yet при n < 15.

- Метрики совпадают с ручным расчётом по выгрузке CSV на 3 учениках.
